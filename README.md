# 새한 프라텍

교대제 공장에서 생산계획에 맞춰 생산 인력을 자동 배치하고, 결근이 생기면 대신 들어갈 사람을 추천해
휴대폰으로 요청하는 웹 서비스입니다. 관리자(지원팀·반장)는 PC에서 배치표를 만들고, 근무자는 휴대폰에서
버튼 하나로 결근 신고·대체 요청 응답·휴무 신청을 합니다.

「원터치 라인 시스템 정리(재구축용)」 명세를 바탕으로 다시 만들었고, 화면은 원터치 라인과 같은 모양입니다.

## 실행

```bash
npm install
npm run dev
```

http://localhost:3000 을 엽니다.

| 들어가는 방법 | 설명 |
| --- | --- |
| 저장된 체험 계정 (첫 화면 오른쪽) | 비밀번호 없이 들어가는 **체험 전용 회사**. admin · worker1 · worker2 · worker3 |
| 관리자 로그인 | 아이디 `admin` + 비밀번호. 첫 비밀번호는 처음 실행할 때 `data/admin-password.txt` 에 적힙니다(`ADMIN_PASSWORD` 환경 변수로 정할 수도 있음). 로그인 후 「설정」에서 바꾸세요. |
| 근무자 로그인 | 아이디 칸에 사번 + 비밀번호. 처음 비밀번호는 전화번호 뒤 4자리이고, 근무자 화면 아래 「비밀번호 바꾸기」에서 숫자 4~8자리로 바꿉니다. |

5번 틀리면 10분 잠기고, 로그인은 30일 유지됩니다.

## 데이터

| 회사 | 내용 |
| --- | --- |
| 새한 프라텍 (`saehan`, 로그인 필요) | **실제 자료.** 2025년 인원배치표·출근부에서 읽은 공장·라인·제품·근무자 |
| 체험 회사 (`demo`, 비밀번호 없음) | 새한 프라텍과 **같은 공장 구조**(라인·제품·사람 수·조·역할·숙련도)에 **이름·사번·전화번호만 가상** |

체험 회사는 누구나 들어올 수 있어서 실제 이름을 보여 주지 않습니다. 「데모 초기화」를 누르면 그때의 새한 프라텍
구조로 다시 만들어집니다.

### 실제 자료 가져오기

2025년 근태 자료 폴더(1공장 `인원배치_…xlsx`·`출근부_…xlsx`, 2공장 `2025년_NN월.xls`)를 읽습니다.

```bash
npm run import:2025 -- "<1공장 근태 자료 폴더>" "<2공장 근태 자료 폴더>"
```

숫자 요약만 보여 주는 미리 보기입니다. 반영하려면 끝에 `--apply` 를 붙입니다(배치 기록이 이미 있으면 `--force` 필요).

- **자리**: 최근 석 달에 사람이 선 라인·고정 자리. 기본 인원은 그 자리에 선 평균 인원
- **제품**: 표기가 제각각이라 띄어쓰기·대소문자만 맞춰 하나로 봅니다. 최근 석 달에 나온 제품만 「사용」
- **근무자**: 출근부에 있는 사람 + 최근 석 달에 5번 이상 배치된 사람. 조는 출근부에서, 없으면 근무한 날짜·교대가
  교대 달력과 가장 잘 맞는 조로 정합니다. 근무 이력(자리·제품별 횟수)이 숙련도와 추천에 쓰입니다
- **기준 생산계획**: 자료의 마지막 날 배치표(「지난번과 같게」의 출발점)
- 자료에 없는 것: **전화번호**(근무자 로그인에 필요 — 「근로자 관리」에서 넣어야 함), 사번(250001부터 새로 매김),
  언어(모두 한국어로 시작), 2공장 성별

실제 이름과 제품명은 저장소(git)에 들어 있지 않습니다. 엑셀 파일에서 읽어 회사 데이터베이스에만 넣습니다.

## 현장 운영 방식 (담당자 확인 내용 반영)

- **근무시간**: 주간 08:00~20:00 · 야간 20:00~08:00. 배치표는 교대 3시간쯤 전(야간이면 17시경)에 나가므로
  그때부터 배치 화면이 다음 교대를 먼저 보여 줍니다. 「배치표 복사」로 글로 복사해 메신저·문자에 붙여 넣습니다.
- **라인 배정**: 생산 제품 → 숙련도 순. 자동 배치는 그 제품을 만들어 본 사람을 먼저, 그다음 숙련도가 높은 사람을 넣습니다.
- **결원 충원**: ① 다른 조의 쉬는 사람 중 **이번 달 실 근무일수가 적은 사람**부터 추천합니다. 전화번호가 함께 나오므로
  전화로 확인한 뒤 「배치」를 누릅니다(모든 근무자의 연락처가 필요 — 「근로자 관리」에 없는 사람 수가 표시됩니다).
  ② 그래도 모자라면 **아웃소싱 업체**에 인원수만 요청합니다. 빈자리가 「업체명-남」(운반&박스) · 「업체명-여」(품질검사원)로
  채워지고, 업체에 보낼 문자 내용이 만들어집니다. 누가 올지는 정해지지 않으므로 사람 명단에는 넣지 않습니다.
  업체는 「기준 정보 → 아웃소싱 업체」 또는 요청하는 자리에서 바로 등록합니다. 월 근태표 엑셀에 업체별 투입 인원 시트가 붙습니다.
- **생산계획**: 주 단위(금요일 야간 ~ 다음 금요일 주간). 「생산계획」 메뉴에서 목요일에 임시로 세우고 금요일에 「계획 확정」.
  수시로 바뀌는 계획은 그 칸만 다시 고칩니다(확정 뒤에도 가능).
- **제품별 필요 인원**: 배치 화면이나 생산계획 칸에서 − / + 로 바꾸면 「이 라인에서 이 제품을 만들 때」의 기준으로 기억합니다.
  한 사람이 두 라인을 보면 한쪽을 0명으로, 한 라인에 2~3명이 서면 그 수로 둡니다.

## Supabase 연결

저장소는 Supabase(Postgres)입니다. 주소와 키는 `.env.local` 에 둡니다(git 제외).

1. Supabase 대시보드 → **SQL Editor** 에 [`supabase/schema.sql`](supabase/schema.sql) 전체를 붙여 넣고 실행합니다.
   표 이름이 모두 `sp_` 로 시작해 같은 프로젝트의 다른 표와 섞이지 않고, 여러 번 실행해도 안전합니다.
2. 대시보드 → **Project Settings → API Keys** 의 secret(또는 `service_role`) 키를 `.env.local` 의
   `SUPABASE_SERVICE_ROLE_KEY=` 뒤에 붙여 넣고 서버를 다시 시작합니다.

「설정」 화면 위쪽에 「저장소: Supabase」로 보이면 연결된 것입니다. 키가 비어 있으면 로컬 파일(`data/saehan.db`)에
저장하고 화면 위에 그 사실을 표시합니다.

- 서비스 키는 서버에서만 씁니다. 저장소(git)·채팅·브라우저 코드에 넣지 마세요.
- 모든 표에 행 단위 보안(RLS)을 켜고 공개 정책을 두지 않아 브라우저는 직접 접근할 수 없습니다.

## Vercel 배포

1. 이 폴더를 GitHub 저장소에 올립니다(`.env.local`, `data/` 는 올라가지 않습니다).
2. Vercel에서 그 저장소를 가져옵니다. Framework Preset은 **Next.js** 로 잡혀야 합니다.
3. Environment Variables 에 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SESSION_SECRET`(아무 긴 무작위 글자)을 넣습니다.
4. 요청 20분 만료는 화면을 열 때마다 처리됩니다. 화면이 닫혀 있어도 처리하려면 `/api/cron` 을 예약 작업으로 부릅니다.

## 구조

```
src/lib      업무 규칙(순수 함수) — 화면·저장소와 무관
  calendar.ts  교대 달력(12일 주기, 공장별 기준일)
  engine.ts    필요 인원 · 근무 가능 판단 · 숙련도 · 배치 점수 · 자동 배치 · 대체 추천
  flows.ts     확정 · 직접 고치기 · 결근 처리 · 요청/응답/만료 · 휴무
  demo.ts      체험 배역 고르기, 데모 시계
  seed.ts      기본 설정, 내장 예시 데이터, 체험 회사 만들기(실제 구조 + 가상 이름)
  i18n.ts      근무자 화면 문구(한국어·영어·몽골어·베트남어·네팔어)
src/server   저장·보안
  schema.ts    표 정의(사람·자리·계획·배치·결근·요청·휴무를 각각 표로)
  backend.ts   Supabase / 로컬 SQLite
  store.ts     회사별 상태 읽기, 바뀐 행만 저장, 버전(rev) 확인
  accounts.ts  로그인·잠금,  session.ts  서명 쿠키,  actions.ts · views.ts  동작과 화면 데이터
src/app      화면(첫 화면, /admin, /worker)과 API
scripts      import-2025.ts(실제 자료), company.ts, gen-schema.ts, inspect-xlsx.ts, seed-preview.ts
```

내장 예시 데이터(`seedDemo`)는 실제 자료를 아직 넣지 않은 새 설치와 테스트에서만 쓰입니다.

## 원터치 라인에서 바뀐 점

화면 모양과 문구는 같고, 명세 9장 「다시 만들 때 고칠 점」을 반영했습니다.

| # | 원본의 문제 | 지금 |
| --- | --- | --- |
| 1 | 비밀번호 없이 누구나 관리자로 들어감 | 관리자 비밀번호 로그인, 근무자는 사번 + 개인 비밀번호. 체험 계정은 별도 체험 회사에서만 |
| 2 | 교대 달력이 6일 주기 가정 | 12일 주기(주간 4 → 휴무 2 → 야간 4 → 휴무 2), 공장별 기준일. 「설정」에서 회사가 직접 고침 |
| 3 | 회사 데이터 전체를 JSON 한 덩어리로 주고받음 | 표 단위로 나누고 바뀐 행만 저장. 화면은 필요한 데이터만 받음 |
| 4 | 요청 20분 만료가 관리자 화면이 열려 있을 때만 처리됨 | 서버가 처리(상시 서버는 1분마다, 서버리스는 요청·`/api/cron` 때) |
| 6 | 사람·라인·제품이 가상 데이터 | 2025년 배치표·출근부 가져오기로 실제 라인·제품·근무자·근무 이력 |
| 7 | 이름·제품명 자유 입력 | 사번·제품 마스터로만 선택(「기준 정보」) |
| 8 | 교대 시간·인정 시간·표준 인원·가동률이 고정된 가정 | 「설정」「기준 정보」에서 회사가 직접 정함 |
| 9 | 공장 간 지원은 설계만 | 다른 공장의 쉬는 사람이 추천 목록에 공장 이름과 함께 나오고 요청·투입 가능 |
| 12 | 서비스 키 노출 | 키는 `.env.local`(git 제외)에만 |

원본 화면에 없던 것: 메뉴 「기준 정보」「설정」, 결근 카드의 「신고 취소」, 근무자 화면의 「비밀번호 바꾸기」.
원본에 있던 것 중 뺀 것: 오른쪽 아래 상담 챗봇 위젯(외부 스크립트).

### 아직 하지 않은 것

- **문자·알림톡 실제 발송(#5)**: 알림은 기록만 합니다. 근무자가 앱을 열어야 요청을 봅니다(화면은 4초마다 갱신).
- **자동 모드**(해결안 자동 진행)와 **2공장 입안 → 결정 결재(#9 일부)**: 확정은 한 번입니다.
- **몽골어·베트남어·네팔어 문구(#10)**: 초안입니다. 원어민 검수가 필요합니다.
- **2025년 배치 기록 자체**: 근무 이력(횟수)만 가져왔고, 날짜별 배치표는 가져오지 않았습니다.
